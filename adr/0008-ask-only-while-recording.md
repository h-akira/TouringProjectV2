# 0008. 質問は走行の記録中だけ受け、日ごとの振り返りをやめる

- 日付: 2026-10-20
- 状態: 採用

## 背景

これまでの要件は、走行を記録していないとき・一時停止中の質問も受け、その質問を「日ごと」にまとめて振り返れるようにしていた（US-C-04・US-D-07）。休憩中や走る前後にも質問するし、記録を始め忘れても会話を失いたくない、という理由だった。そのため、記録の画面は「走行ごと」と「日ごと」の2つの切り口を持ち、両者を独立させる決まり（走行の画面と日ごとの画面を互いに移らない、など）を抱えていた。

スライス2 plan 4a で走行ごとの振り返り（一覧・地図・会話の詳細）ができたところで、残りの日ごとの振り返り（plan 4b）の範囲を決めるときに、利用者がこの前提を見直した。

- 走行に結びつかない質問と、走行に結びつく質問の2種類があると、画面・記録・決まりが二重になり、管理が複雑になる。
- 実際の使い方では、質問するのは走っているときで、走行の外の質問は無くても困らない。
- 旧アプリはアプリを開いているあいだ GPS を動かし続けていた。V2 は質問のあいだだけ位置を取るので電池の問題は小さいが、「GPS を使うのは走行の記録中だけ」と決めたほうが分かりやすい。

## 選択肢

| 案 | 判断 |
|---|---|
| A. 質問は記録中だけ受ける。日ごとの振り返りをやめる | 採用 |
| B. 今のまま（いつでも受け、日ごとでも振り返る） | 不採用。二重の作りが残る |
| C. いつでも受けるが、走行の外の質問は残さない | 不採用。答えた質問がどこにも残らないのは分かりにくい |

A の中で決めたこと（利用者と決めた）:

- 一時停止中も受けない（記録中だけ）。休憩中に聞きたければ再開してから聞く。決まりがいちばん簡単になる。
- 受けないときにインカムのボタンが押されたら、録音を始めず、受けないことを端末の音声で知らせる（一時停止中は「再開すると質問できます」と添える）。ヘルメットの中でも、壊れているのか受けていないのかが分かるように。
- ホームの「押して話す」は、記録していないあいだは押せない形で残し、理由を添える（画面の形を変えない）。
- 始めた質問は、途中で一時停止・終了しても最後まで続け、始めたときの走行に結びつける。
- これより前の、走行に結びつかない質問（開発中の試しの質問だけ）は、端末と DynamoDB から一度だけ手作業で消す。
- 後のスライスの機能も同じ考えにそろえる。地点メモは走行の記録中と一時停止中に書けて、その走行に入る（休憩中にゆっくり書くことが多いため、一時停止中も書ける）。文字での質問は声と同じく記録中だけ。

## 決定

質問は走行の記録中だけ受ける。振り返りは走行ごとだけにし、日ごとの振り返り（SC-15・一覧の「日ごと」の切り替え）をやめる。

## 影響

- 要件: US-C-04・US-C-03.006・US-D-07・US-D-08.009 を取り下げ（番号は詰めない）、US-B-01.006 を足し、US-A-08・US-C-03.005・US-D-06.002・US-D-08.002・US-D-08.006 を直した（`docs/01`・`docs/04`）。画面の一覧・遷移図・モックから SC-15 と日ごとを外した。
- 走行を削除する（スライス3）と、その走行の質問と地点メモも一緒に消える。質問と地点メモは走行の中にしか無いため（US-D-06.002）。
- スライス2 spec の §4.7 に、受ける条件と知らせ方を書いた。plan 4b は、日ごとの振り返りから、この変更の実装に置き換えた。
- Backend は変えない。`POST /asks` の `rideId` は API の上では今も省ける。
- 走行を始め忘れたときの質問は残らない（受けない）。受けないことは声で分かるので、その場で走行を始めてから聞き直せる。
