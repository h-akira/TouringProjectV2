# 0011. API 仕様の正本を親の docs に移し、基本設計を docs に置く

- 日付: 2026-10-22
- 状態: 採用

## 背景

`docs/` には要件・画面・方針・ユニット・契約（01〜07）があったが、システムがどう動くか（構成・流れ・部品の分け方・データの置き方）を書いた文書が無かった。仕組みは spec と plan に散っており、どちらも書いた時点の記録なので、いまの姿を知るにはコードを読むしかなかった。

API 仕様（OpenAPI）は Backend のリポジトリの `openapi.yaml` が正本で、契約（07）がそれを指していた。Android と Backend の両方が従う約束なのに、片方のユニットの中に置かれていた。

`docs/` の文書には、何をやめたか・どのスライスで入れたかといった経緯が混ざり始めていた。

## 選択肢

API 仕様の置き場所:

1. 親の `docs/07a_openapi.yaml` を正本にし、Backend のテストは写し（`docs-parent/`）を読む
2. Backend に残し、`docs/` からリンクする
3. Backend を正本にし、親へ写す仕組みを足す

基本設計:

1. `docs/` に 08 系（全体と、ユニットごと）を置き、いまの決定だけを書く
2. spec に書き続ける

## 決定

- API 仕様は選択肢1。ユニット間の約束は親が持つ、という `docs/` の役割に揃える。写す仕組み（`scripts/sync-docs.sh`）はすでにあり、新しい仕組みは要らない。
- 記録の論理モデルを `docs/07b_datamodel.md` に置く。ユニット間で食い違ってはいけない部分なので契約（07 系）に入れ、DynamoDB のキーと Room の表は各ユニットの基本設計に置く。
- 基本設計は選択肢1。`docs/08_design.md`（全体）と `08a`（Android）・`08b`（Backend）・`08c`（Agent）を置く。CICD は非公開なので書かない。
- `docs/` の 01〜08 には、いまの決定だけを書く。経緯は書かず、理由は adr を参照する。使わなくなった番号は「（欠番）」とだけ書く。モック（`docs/mock/`）は付録なので、この限りでない。

## 影響

- API を変えるときは、親の 07a を直し、Backend に写してからテストを回す。Backend のブランチだけでは API を変えられない。
- 振る舞いか仕組みを変える plan は、関わる 07a・07b・08 系を直すタスクを持つ（CLAUDE.md の「区切り点」）。
- 経緯を知りたいときは、adr・spec・plan・コミットを見る。
