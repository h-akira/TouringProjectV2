# 0005. App を React Native からネイティブ（Kotlin）に移し、新しいリポジトリで作る

- 日付: 2026-10-17
- 状態: 採用

## 背景

スライス1の App は React Native（Expo の Development Build）で作った。TS/TSX が約2,300行、Jest のテストが約1,200行、Kotlin が約550行（`handsfree`・`audio-route`・`ride-service`）。スライス2（走行の記録）の設計を終えたところで、作り方を見直した。

利用者が挙げた理由:

- AI が書くなら、利用者の JS/TS の知識はあまり効かない
- 対象は Android だけ
- React Native でも、結局ネイティブのコードを書く構成になっている
- 実機での確認の手間（利用者が実機をつないで手で確かめる作業）が大きい

## 判断の材料

- **アプリの肝（ハンズフリーの起動・インカムの音声の経路・背面での動作）は、すでにネイティブにある。** React Native はその上に JS の層を乗せているだけで、JS とネイティブのつなぎ目（イベント・ライフサイクル・権限）という不具合の出どころを一つ増やしている
- **つなぎ目は自動のテストから漏れる。** Jest はネイティブの部分を作り物に置き換え、Kotlin 側のテストは JS を動かせない。スライス1の利用者の確認リスト（19項目）のうち、約12項目は配線を確かめているだけのものだったが、この理由で実機に回っていた。Kotlin だけにすれば、Robolectric（JVM）とエミュレーターで AI が確かめられる
- **原因を探す場所が減る。** React Native では TS・Kotlin・Expo の prebuild と config plugin・Gradle のどこが原因かを切り分ける。利用者にネイティブの開発経験が無いなら、言語と層は少ないほうがよい
- **クロスプラットフォームという React Native の最大の利点を使っていない**
- **スライス2はネイティブ寄り。** 何時間も背面で位置を取ること・端末の DB・時刻での自動終了は、前面サービス・Room・AlarmManager がそのまま効く。React Native では、位置を JS で受けると背面で届き方が間引かれないかに賭けることになり、外れればネイティブのモジュールを足すことになっていた
- **時期が良い。** スライス1は実装済み、スライス2は spec のレビュー待ちで plan が無い。後になるほど移す費用が上がる

## 選択肢

| 案 | 判断 |
|---|---|
| A. React Native のまま続ける | 不採用。上の理由 |
| B. スライス2で使う部分だけネイティブに寄せる | 不採用。アプリは1つなので、つなぎ目が増えるだけ |
| C. 全体を Kotlin に移す | 採用 |

移すかどうかを、小さなスパイク（Kotlin で質問の一巡だけを作り、自動で確かめられる項目を数える）で決める案もあった。利用者の判断で、スパイクを省いて移すと決めた。

リポジトリは、今の App のリポジトリをブランチの上で置き換える案と、新しく作る案があり、新しく作る（`TouringProjectV2_Android`）と決めた。React Native 版は凍結して残す。

## 決定

- App を Kotlin・Jetpack Compose で作り直す。リポジトリは `TouringProjectV2_Android`（親の submodule `Android/`）
- まずスライス1の App と同じ振る舞いに戻し（[移行の設計](../docs/specs/2026-10-17-native-migration-design.md)）、そのあとスライス2に進む
- 今の Kotlin（`handsfree`・`audio-route`・`ride-service`）は、React Native のモジュールの皮を外して移す

## 影響

- 体で確かめるしかない項目（インカムのボタン・インカムのマイクと出力・音量の聞き比べ・走行用のビルドでの通し）は、ネイティブ版でもう一度確かめる。スライス1の plan 4b で分かったこと（回答の音量は +6dB が上限・SCO 中のメディアの音量・release の権限）も確かめ直す
- [0004](0004-background-processing.md) の「一巡の処理を JS に置く」「`setTimeout` の代わりにネイティブで待つ」は、ネイティブ版には当てはまらない。一巡はサービスの中のコルーチンで動かす。前面サービスで生かすこと・マナーモードでも鳴らすこと・回答の時点で URL から再生することは引き継ぐ
- 失うもの: JS のホットリロード、Expo のライブラリ（Android 標準の API で置き換える）
- 移行を終えたら、親から submodule `App/` を外し、`TouringProjectV2_App` はアーカイブする
