# 0004. 背面での回答待ちと読み上げは、JS とフォアグラウンドサービスで行う

- 日付: 2026-10-16
- 状態: 一部置き換え（[0005](0005-native-android-app.md)。JS に置く部分はネイティブ版には当てはまらない）

## 背景

既定では、質問を送った時点でナビのアプリへ戻り、回答待ち（ポーリング）と読み上げはアプリが背面にあるまま行う。これが Android で成り立つかを、実機（Android 16）で、ナビを表示した状態で確かめた。

| 条件 | 画面 | JS の処理 | 読み上げ |
|---|---|---|---|
| フォアグラウンドサービスあり・待ちに `setTimeout` | 点灯 | アプリを前面に戻すまで止まった | 鳴らない |
| フォアグラウンドサービスあり・待ちをネイティブで行う | 点灯 | 最後まで動いた | マナーモードで鳴らない（下記） |
| 同上＋マナーモードでも鳴らす指定 | 点灯 | 最後まで動いた | 鳴った（インカム） |
| 同上・回答の時点で URL から音声を読み込む | 消灯 | 最後まで動いた | 1〜3秒の読み込みの後に鳴った |
| フォアグラウンドサービスなし・同上 | 消灯 | 約70秒で止まった | 読み込みが進まず鳴らない |

- React Native は、アプリが背面に回ると JS のタイマーを止める。JS の処理そのものは、フォアグラウンドサービスがあれば動き続ける。
- expo-audio は、端末がマナーモードのとき、`playsInSilentMode` を指定しないと再生の指示を黙って無視する（出力先がインカムでも同じ）。
- フォアグラウンドサービスが無いと、画面を消したあと通信と再生が止まる。

## 選択肢

| 案 | 判断 |
|---|---|
| A. 一巡の処理を JS に置き、フォアグラウンドサービスでプロセスを生かす | 採用。上の条件を守れば、画面を消しても成り立った |
| B. ポーリングと再生をネイティブのサービスに置く | 不採用。A で成り立つので、ネイティブのコードを増やさない |

## 決定

- 一巡の処理は JS に置く。録音を始めるときにフォアグラウンドサービス（種類は microphone と mediaPlayback）を始め、一巡が終わったら止める。
- 背面で待つ処理には `setTimeout` を使わず、ネイティブ側で時間差で解決する待ちを使う。
- 音声の設定は、背面で再生する・マナーモードでも鳴らす・他のアプリの音と重ねる、を指定する。
- 回答の音声は、回答が届いた時点で、その URL から再生を始める。

## 影響

- App のネイティブモジュールに、フォアグラウンドサービスと、ネイティブで待つ関数を持たせる。
- 確かめていないこと: USB を外した状態、90秒を超える待ち、ナビの案内の音声と重なったときの聞こえ方。App の実機での確認で見る。
