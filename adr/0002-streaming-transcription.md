# 0002. 音声の質問はストリーミングで文字にする

- 日付: 2026-10-16
- 状態: 採用

## 背景

音声の質問214件の計測で、段ごとの所要時間は次のとおりだった。

| 段 | 中央値 | 90% | 最大 |
|---|---|---|---|
| 文字起こし（バッチのジョブ。受け付けから完了の通知まで） | 9.2秒 | 26.6秒 | 219.9秒 |
| 回答の生成と音声合成 | 7.3秒 | 14.4秒 | 25.1秒 |

60秒を超えた10件は、どれも文字起こしだけで47〜220秒かかっていた。録音の大きさ（平均92〜105KB）とは関係が無く、バッチのジョブの待ちと揺れが原因と考えられる。

## 選択肢

| 案 | 判断 |
|---|---|
| A. バッチの文字起こし（S3 に置いてジョブを投げ、完了の通知を待つ） | 却下。上の揺れがそのまま残る |
| B. ストリーミングの文字起こしを、サーバー側（worker）から録音のファイルを流し込んで呼ぶ | 採用。ジョブの待ちが無い。App は AWS の認証情報を持たずに済み、門番も保てる |
| C. App からストリーミングの文字起こしを直接呼ぶ | 却下。App に AWS の認証情報が要る |

## 決定

- worker が、受け取った録音のファイルを Transcribe のストリーミング（`ja-JP`）に流し込んで文字にする。
- ストリーミングが受け付ける形式は PCM・FLAC・Ogg/Opus。スパイクの結果から、録音は PCM（16kHz・モノラル・16bit）にし、expo-audio の AudioStream で録る。
- 録音のファイルは、実時間に合わせず一気に流し込む。

## 確かめること（スパイク A）

- Lambda から録音のファイルを一気に流し込めるか（実時間に合わせて送る必要があるか）。
- 文字起こしの所要時間と、日本語の聞き取りの質。
- 実機で、インカムのマイクから Ogg/Opus と PCM のどちらが録れ、どちらがよく聞き取られるか。

## 結果

## 結果（2026-10-16 のスパイク）

| 条件 | 一気に流し込めたか | 所要時間（ストリームの開始から文字が確定するまで） | 聞き取り |
|---|---|---|---|
| 手元・Ogg/Opus・合成音声（3秒／7秒） | できた | 2.3秒／5.4秒 | 正確 |
| 手元・PCM・合成音声（3秒／7秒） | できた | 1.8秒／4.7秒 | 正確 |
| 手元・Ogg/Opus・合成音声に雑音を混ぜたもの（3秒／7秒） | できた | 2.6秒／5.2秒 | 3秒は正確。7秒は「給油」が「吸引」になるなど誤りあり |
| 手元・実時間に合わせて送る（参考） | — | 3.6〜9.8秒 | — |
| Lambda（Python 3.13・arm64・512MB）・Ogg/Opus と PCM | できた | 1.6〜2.6秒（3秒）／5.3〜5.7秒（7秒）。初期化は約0.2秒 | 正確 |
| 実機（インカムのマイク）・MediaRecorder の Ogg/Opus | 拒否された（`The data is corrupted.`） | — | 同じ音声を中身を変えずに詰め直すと受け付けられ、正確 |
| 実機（インカムのマイク）・AudioStream の PCM（6秒） | できた | 3.4秒 | 正確 |

- Android の MediaRecorder が書く Ogg のコンテナは、ストリーミングの文字起こしに受け付けられない。使うにはサーバーで詰め直す処理が要るので、Ogg/Opus はやめる。
- PCM は1秒あたり32KB。録音の上限の60秒でも、base64 で約2.6MB に収まる。
- 確かめていないこと: 走行中の騒音下での聞き取り、録音の音源の違い、インカムのボタンで張った経路での録音。App の実機での確認で見る。
