## 4. 進行方位（US-A-02）

### 4.1 材料

- 方位の材料は、**今の走行の、最後の区間（開始か、最後の再開のあと）のルートの点**。ルートの点は今のとおり、記録中に5秒ごと・前の点から10m 以上動いたときに足され、精度が50m より悪い点は除かれている（US-C-02.005・.006）。
- 一時停止の前の区間の点は使わない。フェリー・電車などで離れた場所から再開することがあるため（US-C-07.005）。一時停止中に地点メモを開いたときは、一時停止の直前の区間の点を使う（§4.2 の保つ上限が効く）。
- 今の位置は、今のとおり、質問では録音を終えたときの位置（30秒以内）、地点メモでは開いたときの位置。文字の質問では、送った時点の位置（30秒以内）を使う。
- 質問の録音のあいだに集めた位置は、今の位置を決めるのにだけ使う。

### 4.2 求め方

ルートの点を新しいほうから遡り、次の両方を満たす**最初の点**を基準にする。方位は、基準の点から今の位置への向き（真北から時計回りの度数。0以上360未満）。

- 位置の精度が**精度の上限**以内（精度が分からない点は使える）
- 今の位置から**基準の距離**以上離れている

次のときは方位なし（null）とする。AI には今のとおり「進行方向: 不明（方角や左右には触れないこと）」と渡す。

- 今の位置が無い、または今の位置の精度が精度の上限より悪い
- 基準の点が見つからない（区間の始めから基準の距離ほども動いていない）
- 基準の点が**保つ上限**より古い

この決まりで、場面ごとに次のようになる。

| 場面 | 基準の点 | 方位 |
|---|---|---|
| 走っている | 数秒前の点 | 今の向き |
| 曲がった直後 | 曲がったあとの点（新しい点ほど今の向きに近い） | 曲がったあとの向き。曲がってから基準の距離を進むまでは、曲がる前後を結んだ向きになる |
| 信号待ち（止まって2分） | 止まる直前に走ってきた区間の点（止まっているあいだは点が増えない） | 止まる直前の向き |
| 止まって保つ上限を超えた | 保つ上限より古い | なし |
| 走り出した | 走り出したあとの点 | 新しい向き |

### 4.3 パラメーター

利用者が SC-22 で変える。アプリの設定として保存し、変えるとすぐ次の計算から効く（SSM には置かない）。

| パラメーター | 選べる値 | 既定 |
|---|---|---|
| 基準の距離 | 10・15・20・30 m | 15 m |
| 精度の上限 | 10・20・30・50 m | 20 m |
| 保つ上限 | 2・5・10・30 分 | 10 分 |

既定の保つ上限（10分）は、長い信号待ちや踏切より十分に長く、休憩（ふつうは一時停止する）よりは短い値にした。

### 4.4 契約（Backend）

- `POST /asks`・`PUT /asks/{askId}/offline`・`PUT /rides/{rideId}/notes/{noteId}` に、`headingDegrees`（0以上360未満の数、または null）を足す。
- Backend は `headingDegrees` があればそのまま使い、記録に残し、Agent への問いの方位にする。0以上360未満の数でなければ方位なしとして扱う（今の `headingSample` の「不正なものは無いものとして扱う」と同じ）。
- `headingSample` も今のまま受ける。端末に残っている、版を上げる前に作った未送信の質問できなかった地点・地点メモのため。両方あれば `headingDegrees` を使う。Android は新しく作るものには `headingSample` を送らない。
- `headingSample` の受け口を外す時期は、Backend の issue にする（版を上げてから、未送信が残っていないことを確かめたあと）。
- 07 の UC-5「方位の材料」と 07a を直す。

### 4.5 SC-22 位置と方位の確認

設定（SC-09）の一覧の「位置と方位の確認」から開く。走行中の画面ではなく、停車中に GPS が正しいかを確かめる画面（SC-12 の録音の確認と同じ位置づけ）。

- 開いているあいだ、次をその場で更新して出す。
  - 今の位置の精度（m）
  - 方位（16方位と度数）・右手と左手の方角
  - 基準にした点の距離（m）と何秒前か
  - 方位なしのときは、その理由（今の位置が無い・精度が悪い・まだ動いていない・止まって保つ上限を超えた）
- 走行の記録中は、走行のルートの点で計算する。記録していないときは、この画面が開いているあいだに集めた点（ルートと同じ間隔と距離で集める）で計算する。どちらも §4.2 と同じ計算なので、画面に出た方位がそのまま AI に渡る方位になる。
- 画面の下に §4.3 の3つのパラメーターを並べる。「既定値に戻す」は確認を出さず、トーストで知らせる。
- 画面を離れたら、位置の監視を止める（記録中のルートの監視は止めない）。

## 5. 文字での質問（US-A-08）

### 5.1 入口

- ホームの上部の「🎤 押して話す」の隣に「⌨ 文字で質問」を置く。押して話すと同じく、テスト・停車中のための目立たない操作（US-B-05.006）。
- 押せるのは走行の記録中だけ。記録していないとき・一時停止中は押せない形にして、押して話すと同じ理由を添える（US-B-01.006）。
- 受け付けるかどうかの判断は、ホームと質問の一巡の司令塔で1つにまとめる。断られる場面のテストを足す（Android #48）。

### 5.2 入力のシート

- 下から開くシート（SC-02 の一部）。入力欄（500字まで。残りの字数を出す）・「質問する」・「やめる」。
- 空白だけのときは「質問する」を押せない。

### 5.3 一巡

- 「質問する」で `POST /asks` に `text` を送る。位置と方位は §4 と同じに求める。会話の文脈・回答の音量・走行の識別子は声の質問と同じ。
- 送ったらシートを閉じ、SC-03 の回答待ちから始める（録音と文字起こしは無い）。回答は読み上げる（US-A-08.003）。
- 画面から始めた質問なので、戻り先のアプリには戻らない（US-B-04.002）。失敗は画面に出す（US-B-06.004）。
- **通信できないとき**は、質問できなかった地点を作らない。シートを閉じずに「通信できません」と出し、打った文を残したまま送り直せるようにする。停車中でやり直せるため。声の質問は今のまま、質問できなかった地点を作る（US-C-09）。
- 回答待ちで取り消したときの扱いは声の質問と同じ（端末に残さない）。

### 5.4 記録（Room 版7）

- 端末の質問の行に、入力が声か文字か（`inputType`。`audio`・`text`）を足す。版7の移行では、今ある行を `audio` にする（今までの質問はすべて声）。
- 文字の質問では、質問の文に打った文を入れる。
- `GET /records` の `inputType` を、読み込みで埋める（今は読み捨てている）。
- SC-07 の「入力」に「🎤 声で質問」か「⌨ 文字で質問」を出す（US-A-08.004）。
- 文字の質問は録音が無いので、SC-12 には出ない。

## 6. SC-11 録音の設定

- 設定（SC-09）の一覧に「録音の設定　上限 20秒 · 合図 1.5秒」の行を置き、SC-11 を開く。

| 項目 | 選べる値 | 既定 |
|---|---|---|
| 録音の上限 | 10〜60秒（5秒刻み） | 20秒 |
| 開始の合図 | なし・0.5・1・1.5・2・3秒 | 1.5秒 |

- 開始の合図の既定は、今の合図の長さ（1.5秒）に合わせる。インカムは音の頭を落とすので、短いと聞こえにくいことを説明に書く。
- 変更はすぐ保存し、次の質問から効く。SC-12 の試し録りも同じ値を使う（US-E-03.001）。
- 「既定値に戻す」は2項目を既定に戻す。確認は出さず、トーストで知らせる。
- SC-11 から SC-12 へは移らない（SC-12 へは設定の一覧から入る）。
- SC-19 の声の入力（上限60秒）は質問ではないので、SC-11 の値を使わない。
- 録音の上限は、Backend の受ける長さ（0.25〜60秒）に収まる。

## 9. 後回しの指摘

直し方は、各 issue の「対応案」に従う。対応案に選択肢があるものは次のように決める。

| 指摘 | 決めたこと |

| Backend #6 | 改行入りの base64 を受け入れる |
| Backend #7 | SSM の設定値の名前を、環境の名前（`Environment`）から組み立てる |
| Agent #2 | まずログで、質問ごとに MCP の接続をやり直しているかを確かめる。やり直していれば、接続を使い回す |

直さずに閉じるもの（spec のコミットのときに、理由を書いて閉じる）:

- Backend #5: 身内だけで、ほぼ一人で使う前提（US-E-06.009）。上限に届く使い方をしていない
- Agent #6: App の質問の一巡は1つずつ（回答待ちのあいだは次を始めない）。文字での質問を足しても同じなので、起きる経路が無い

新しく立てる issue:

- Agent: AI の費用を下げる検討（モデルの変更など）。扱う時期は、費用が気になったとき
- Backend: `headingSample` の受け口を外す（§4.4）。扱う時期は、版を上げて未送信が残っていないことを確かめたあと

直したコミットか PR に `Fixes #N` を書く。

| 場面 | 振る舞い |

## 11. テスト

- **方位（JVM）**: §4.2 の表の各場面と、精度の悪い点を飛ばす・一時停止の前の区間を使わない・パラメーターを変えると次の計算から効く。SC-22 の計算が質問と同じ関数を通ることも確かめる。
- **文字での質問（JVM）**: シートの字数と空白・記録中だけ押せる（#48 の、断られる場面を含む）・回答待ちから始まる・戻らない・通信できないと文が残り地点を作らない・`inputType` の保存と読み込み・Room 版6→7の移行。
- **SC-11（JVM）**: 値が次の質問と試し録りに効く・既定値に戻す・合図なし。
- **Backend（pytest）**: `headingDegrees` の受け取りと範囲の外・`headingSample` との両方・3つの経路。指摘ごとのテスト。07a を写してから回す。
- **Agent**: 指摘ごとのテスト。
